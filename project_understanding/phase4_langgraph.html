Phase 4 — LangGraph Multi-Agent

State Machine Overview

Entry: router_node
    │
    ├── intent == "relationship_lookup" ──→ graph_node
    │
    └── everything else ──────────────────→ retrieval_node
                                                  │
                                    ┌─────────────┘
                                    ▼
                              analysis_node   ← only node that calls LLM
                                    │
                              grounding_node  ← regex check, sets confidence
                                    │
                    confidence >= 0.6 ──→ END
                    confidence < 0.6  ──→ human_approval_node ──→ END

State Shape

class AgentState(TypedDict):
    query: str               # input: the user question
    intent: str              # set by router: spec_lookup | relationship_lookup | general
    retrieved_chunks: list   # set by retrieval_node
    graph_results: list      # set by graph_node (component names)
    context: str             # combined text passed to the LLM
    answer: str              # set by analysis_node
    confidence: float        # set by grounding_node (0.0 - 1.0)
    grounding_passed: bool   # True if confidence >= threshold
    requires_human_review: bool
    human_decision: str      # approve | escalate

How LangGraph Nodes Work

Each node function receives the full state dict and returns a PARTIAL dict of only the keys it updated. LangGraph merges the return into the state — you don't need to copy the whole state forward.

# Node function signature:
def router_node(state: AgentState) -> dict:
    intent = classify(state["query"])
    return {"intent": intent}   # only return what changed

# NOT this:
def router_node_wrong(state):
    state["intent"] = classify(state["query"])
    return state   # returning full state also works but is unnecessary

Conditional Edges

def route_after_router(state: AgentState) -> str:
    return "graph_search" if state["intent"] == "relationship_lookup" else "retrieval"

graph.add_conditional_edges(
    "router",            # from node
    route_after_router,  # routing function returns a string key
    {
        "retrieval":    "retrieval",    # key -> next node
        "graph_search": "graph_search",
    }
)

Provider-Agnostic Design

The only function that touches the LLM is call_llm_with_fallback() in resilience.py. The LangGraph graph structure, the router, the grounding check — none of that changes between the local (Ollama) and AWS (Bedrock) versions.

Interview talking point: "My router is deterministic — it uses regex patterns to classify intent, not an LLM call. That keeps routing latency under 1ms and makes routing decisions auditable. The LangGraph state machine handles branching; only the analysis node calls the LLM. Swapping Ollama for Bedrock touches one function."
