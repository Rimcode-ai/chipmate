Phase 8 — Observability

What a Trace Shows

Query: "What is the voltage of TPS62902?"

Trace (total: 3.2s)
  └── router_node          12ms    intent=spec_lookup
  └── retrieval_node       180ms   chunks=5, model=nomic-embed-text
  └── analysis_node        2800ms  model=mistral:7b, method=primary
  └── grounding_node       8ms     confidence=0.85, passed=true

The bottleneck is visible: Ollama inference (2.8s). Retrieval is fast (180ms including embedding). This is the kind of data you need to answer "where is the latency?" in an interview.

Langfuse vs OpenTelemetry

FeatureLangfuse (tracing.py)OpenTelemetry (tracing_alternative1.py)
LLM-specific conceptsPrompt, completion, token count, costManual span attributes
LangChain integrationOne CallbackHandler importWrap each node manually
BackendLangfuse UI (self-hosted or cloud)Jaeger, Zipkin, Datadog, X-Ray
PortabilityLangfuse-specificVendor-neutral standard
AWS equivalentX-Ray (aws/tracing_aws.py)OTLPSpanExporter to X-Ray

Langfuse Usage (one line)

from local.tracing import trace_query

result = trace_query(query="What is the voltage of TPS62902?", app=app, initial_state=state)
# → prints trace URL: http://localhost:3000/traces/abc123

X-Ray on AWS

from aws_xray_sdk.core import patch_all
patch_all()  # auto-instruments all boto3 calls (Bedrock, DynamoDB, S3)

# Custom subsegment per node:
with xray_recorder.in_subsegment("analysis_node") as seg:
    seg.put_annotation("model", "claude-3-haiku")
    answer = call_bedrock(prompt, context)

Enable X-Ray on Lambda

aws lambda update-function-configuration \ --function-name chipmate-api \ --tracing-config Mode=Active
# View traces: AWS Console > X-Ray > Service Map

Run Commands (Local)

# Start Langfuse: docker compose up -d langfuse
# Open http://localhost:3000 — create account, add keys to .env
python -m local.agent --query "What is the voltage of TPS62902?"
# Open Langfuse UI > Traces — verify trace with all spans appears
python -m local.tracing_alternative1 # runs OTel console demo
Interview talking point: "I traced every agent step — router, retrieval, analysis, grounding — as a separate span. Locally I used Langfuse because it understands LLM concepts natively (prompt, completion, cost). On AWS I used X-Ray, which Amazon uses internally, with patch_all() to auto-instrument boto3. Both show the same breakdown: my latency bottleneck is LLM inference, not retrieval."
