Phase 5 — Deterministic Evaluation

The Core Idea

The LLM can confidently state a wrong answer. Confidence is not correctness. The grounding check in the agent (and the eval harness) verifies factual claims by extracting numeric values from the answer with regex and checking if those values appear in the retrieved source text.

Answer:  "The TPS62902 operates at 3.3V"
Source:  "Input Voltage Range ... 3V to 17V"

Regex extracts: ("3.3", "v") from answer
Checks: does "3.3 v" appear in source text? → NO → FAIL (grounding gap)

Correct answer: The source says 3V–17V, not specifically 3.3V.
An LLM hallucinated a specific value from a range.

Two Eval Approaches

eval.py — Regex grounding (USED)

  • Extract (value, unit) pairs from the answer
  • Check each against the source context text
  • Deterministic: same input → same verdict always
  • Fast: no LLM call during eval
  • Limited: can't evaluate fluency or completeness

eval_alternative1.py — LLM-as-judge

  • Send question + expected + actual to LLM
  • LLM scores 1-5 with justification
  • Non-deterministic: can vary between runs
  • Captures quality dimensions regex misses
  • Use as complement, not replacement

Golden Dataset Format

{
  "id": "tc-001",
  "query": "What is the input voltage range of TPS62902?",
  "intent": "spec_lookup",
  "expected_value": "3",
  "expected_unit": "V",
  "expected_source_contains": "Input Voltage"
}

{
  "id": "tc-002",
  "query": "What replaces the TPS62902?",
  "intent": "relationship_lookup",
  "expected_graph_result": ["TPS62903"]
}

Accuracy Scoring

PASS:    full credit (1.0)
PARTIAL: half credit (0.5) — value found but unit missing, or some expected parts found
FAIL:    no credit (0.0)
SKIP:    excluded from denominator

Accuracy = (PASS + 0.5 * PARTIAL) / (total - SKIP)

Run Commands

python -m local.eval --dataset golden_dataset.json
python -m local.eval --dataset golden_dataset.json --verbose
python -m local.eval_alternative1 --dataset golden_dataset.json
# Compare both scores — note where they disagree
Interview talking point: "My evaluation is deterministic — I extract claimed values with regex and compare them against the retrieved source text. This is infrastructure-agnostic: the same eval script works against Ollama locally and Bedrock on AWS. An LLM judge adds non-determinism to the evaluation layer, which makes the eval less reliable than the system being evaluated."
