Phase 1 — ingest.py: Full Walkthrough

Code flow first, then line-by-line following execution order. Lead Engineer → Ducky Duck teaching format.

Part 1 — The Execution Flow

When you run this command:

python -m local.ingest --input data/datasheets/TPS62902.pdf

Python does NOT run the file top-to-bottom in the order it is written. Here is the actual execution sequence:

1 Module load (top of file) Runs imports, creates constants, registers function definitions. Does NOT run any function bodies yet.
2 if __name__ == "__main__": This evaluates to True because you ran the file directly. Enters the block.
3 argparse reads the terminal Reads --input and --output flags. Sets args.input and args.output.
4 Path.mkdir() Creates data/chunks/ directory if it does not already exist.
5 ingest_pdf() called Execution jumps into the function. Opens the PDF. Starts page loop.
6 pdfplumber.open() Opens the PDF file. pdf.pages is now a list of Page objects.
7 for page_num, page in enumerate(...) Loops page 0, page 1, page 2 … until all pages are processed.
8 chunk_text_by_section() called For each page: splits page text into lines, scans for section headers, flushes buffers into chunks.
9 is_section_header() called Called for every non-blank line. Tests the line against the HEADER_RE regex. Returns True or False.
10 extract_tables_as_chunks() called For each page: detects tables, converts rows to pipe-separated text, saves each table as one chunk.
11 chunk tagging loop Every chunk from text + tables gets chunk_id, component, source_file added. Appended to all_chunks.
12 ingest_pdf() returns Returns all_chunks — one flat list of every chunk from every page of the whole PDF.
13 json.dump() Writes the chunk list to data/chunks/TPS62902.json.
14 print() Prints summary: total count and 3 sample chunks.
The one-sentence summary: The __main__ block reads your terminal command and calls ingest_pdf(), which opens the PDF page by page — for each page it splits text into section-bounded chunks and tables into single-unit chunks, tags every chunk with a unique ID and metadata, collects them all, and when done the __main__ block saves the result to a JSON file and prints a summary.

Part 2 — Line-by-Line, Following Execution Order

Step 1 — Module Load: Imports & Constants

import re
import json
import argparse
from pathlib import Path
import pdfplumber
👩‍💻
Lead

Before your code does anything useful, Python goes shopping for tools. These five lines are the shopping list. Each import brings a toolkit into scope.

re — the regular expression module. A regex is a pattern that describes what text looks like. We use it to recognise lines like "ELECTRICAL CHARACTERISTICS" as section headers.

json — a serialiser. Converts Python objects into text that can be saved to a file and loaded back later.

argparse — reads what the user typed in the terminal. Without it, --input and --output flags would not work.

from pathlib import Path — Path is a smart wrapper around file paths. A plain string like "data/chunks" is dumb — it is just characters. A Path object knows how to extract the filename, create directories, join paths, and handle OS differences (Mac uses /, Windows uses \).

pdfplumber — the only third-party library here. It cracks open a PDF and hands you the text and tables as Python objects. Without it you would be staring at binary gibberish.

🐥
Ducky

Why not just use a string for the file path? Why do I need Path?

👩‍💻
Lead

Try joining a folder and a filename as plain strings: "data/chunks" + "/" + "TPS62902.json". Works on Mac, silently breaks on Windows which uses backslash. Path("data/chunks") / "TPS62902.json" works everywhere because Path knows the OS. Also, path.stem, path.name, path.mkdir() are all built in — you stop writing utility code and focus on business logic.

HEADER_RE = re.compile(r'^[A-Z][A-Z0-9\s\-/]{3,}$')
MIN_CHUNK_CHARS = 50
👩‍💻
Lead

These are module-level constants — created once on file load, alive for the entire program. Written in UPPER_CASE by convention to signal "do not mutate this inside a function."

re.compile() pre-processes the regex pattern into a compiled object. If you wrote re.match(pattern, line) inside a loop, Python would re-parse the pattern string on every single iteration — potentially thousands of times. Compiling once here means the parsing cost is paid once.

Regex pattern decoded

PartMeaningExample match
r'...'Raw string — backslashes are literal, not Python escape chars—
^Must match at the START of the stringNothing before the first character
[A-Z]Exactly one uppercase letterE in ELECTRICAL
[A-Z0-9\s\-/]A character class: uppercase letter, digit, whitespace, hyphen, or slashL, , -
{3,}The character class above, repeated 3 or more timesECTRICAL CHARACTERISTICS

🐥
Ducky

Why 50 characters for MIN_CHUNK_CHARS? Why not 30 or 100?

👩‍💻
Lead

It is a judgment call. When pdfplumber extracts text, it sometimes returns noise — a page number like "3", a stray logo abbreviation like "TI", a single value like "3.3". None of those are useful chunks for retrieval. 30 lets in too much noise. 100 throws away short-but-valid entries like a one-line spec. 50 is a reasonable middle ground for datasheet content. In production you would tune it by inspecting what gets dropped. For now, 50 works.

Step 4 — create the output directory

Path(args.output) wraps the string "data/chunks" as a Path object. .mkdir() creates the directory.

Step 5 — ingest_pdf() is called

    chunks = ingest_pdf(args.input)

Execution jumps into the function. Everything below is happening inside ingest_pdf().

def ingest_pdf(pdf_path: str) -> list[dict]:
    path = Path(pdf_path)
    component = path.stem.upper()
    all_chunks = []
    current_section = "GENERAL"
    chunk_index = 0
👩‍💻
Lead

path.stem extracts the filename without its extension. Path("data/datasheets/TPS62902.pdf").stem gives "TPS62902". .upper() normalises it in case someone named their file tps62902.pdf.

Three variables initialised before the loop:

all_chunks — the master list. Every chunk from every page of the entire PDF ends up here. Returned at the end.

current_section — tracks which section we are inside. Starts as "GENERAL" because no section header has been seen yet. Updates every time a header is found, and crucially — carries across page boundaries.

chunk_index — a simple integer counter. Increments by 1 for every chunk saved. Used to generate unique IDs like TPS62902_p003_c012.

🐥
Ducky

Why does current_section need to carry across page boundaries?

👩‍💻
Lead

A section in a real datasheet can span multiple pages. "Electrical Characteristics" might start on page 4 and continue on page 5 with no header at the top of page 5. If you reset current_section to "GENERAL" at the start of every page, all the content on page 5 would be wrongly tagged as "GENERAL". By carrying the last seen section forward, chunks on page 5 correctly stay tagged as "ELECTRICAL CHARACTERISTICS".

Step 6 — open the PDF

    with pdfplumber.open(pdf_path) as pdf:
👩‍💻
Lead

with ... as pdf: is a context manager. It opens the file, gives you access to it via the name pdf, and guarantees the file is closed when the indented block exits — whether that exit is normal or due to an exception. It is the safe alternative to manually calling pdf.close().

Think of it like a library checkout desk. with checks the book out. When the indented block ends, the book is automatically returned — even if you tripped and fell on the way out.

Step 7 — loop over pages

        for page_num, page in enumerate(pdf.pages):
👩‍💻
Lead

pdf.pages is a list of pdfplumber Page objects — one per page in the PDF.

enumerate() wraps any iterable and yields (index, value) pairs. First iteration: page_num = 0, page = <Page 0>. Second: page_num = 1, page = <Page 1>. And so on.

🐥
Ducky

Why not just for page in pdf.pages?

👩‍💻
Lead

Because you need the page number to tag each chunk with where it came from. for page in pdf.pages gives you the page object but no counter. enumerate() gives you both at once. Never write a separate page_num = 0 counter that you increment manually — enumerate() is the right tool.

Step 8 — chunk_text_by_section()

            page_text = page.extract_text() or ""
            text_chunks, current_section = chunk_text_by_section(page_text, page_num, current_section)
👩‍💻
Lead

page.extract_text() returns all the text on this page as one big string with \n between lines. On an image-only page it returns None. or "" converts None to an empty string — safe to pass into the function either way.

text_chunks, current_section = ... is tuple unpacking. The function returns two values packaged as a tuple: (list_of_chunks, section_name). Python assigns each to the corresponding variable on the left. The updated current_section will be passed into the next page's call.

Now execution jumps into chunk_text_by_section():

def chunk_text_by_section(text: str, page_num: int, current_section: str) -> tuple[list[dict], str]:
    lines = text.split("\n")
    chunks = []
    buffer = []
👩‍💻
Lead

text.split("\n") cuts the page string at every newline and returns a list. "Line one\nLine two\nLine three" becomes ["Line one", "Line two", "Line three"].

chunks collects finished chunk dicts — the final output of this function. buffer is a temporary holding area. As we scan lines one by one, we accumulate them here. When we hit a section header, we flush the buffer into a chunk and reset it. Think of buffer as a notepad — you write on it until a new section begins, then you tear off the sheet and file it.

    for line in lines:
        stripped = line.strip()
        if not stripped:
            continue
👩‍💻
Lead

.strip() removes leading and trailing whitespace. " Voltage 3.3V " becomes "Voltage 3.3V".

if not stripped: continue — after stripping, if the result is an empty string, not stripped is True. continue immediately skips to the next loop iteration. Blank lines carry no content — discard them.

        if is_section_header(stripped) and buffer:
            body = " ".join(buffer).strip()
            if len(body) >= MIN_CHUNK_CHARS:
                chunks.append({"text": body, "section": current_section, "page": page_num})
            current_section = stripped
            buffer = []
        else:
            buffer.append(stripped)
👩‍💻
Lead

The condition has two parts joined by and — both must be true:

1. is_section_header(stripped) — the current line matches the all-caps regex.

2. buffer — the buffer is non-empty. A non-empty list is truthy in Python. An empty list is falsy. This prevents saving an empty chunk when two headers appear back to back.

If both are true: join the buffer into one string with spaces between each line, check it is at least 50 characters, save it as a chunk dict with the current section name, then update current_section to the new header and reset buffer.

Notice: the chunk is tagged with the section that was active while the buffer was being filled, not the new header. The new header belongs to the next chunk.

If the line is not a header: just append it to the buffer and keep going.

🐥
Ducky

What if the very first line on a page is a section header? The buffer is empty, so the first condition fails. What happens?

👩‍💻
Lead

It falls into the else branch — buffer.append(stripped). The header line gets added to the buffer as if it were regular content. That means the header text itself ends up in the next chunk's body.

Is that a problem? Not really for our use case — the section name is tracked via current_section, and the header text appearing in the body too is harmless. If it bothered you, you could add a special case: if it is a header and the buffer is empty, just update current_section and do not add to the buffer. That would be a clean improvement.

    # flush remaining buffer
    if buffer:
        body = " ".join(buffer).strip()
        if len(body) >= MIN_CHUNK_CHARS:
            chunks.append({"text": body, "section": current_section, "page": page_num})

    return chunks, current_section
👩‍💻
Lead

The flush-on-header logic inside the loop only triggers when it sees a new header. The last section on the page never gets a header after it — the page just ends. So those lines are still sitting in the buffer when the loop finishes. This block handles that: if the buffer is non-empty after the loop, flush it as one final chunk.

return chunks, current_section — returns two values. Python automatically packages multiple return values into a tuple. The caller unpacks them with text_chunks, current_section = ....

Step 9 — is_section_header() (called from inside the loop)

def is_section_header(line: str) -> bool:
    return bool(HEADER_RE.match(line.strip()))
👩‍💻
Lead

HEADER_RE.match(line.strip()) — tries to match the compiled regex against the string. Returns a match object if it matches, None if it does not.

bool(...) — converts the result to True or False. A match object is truthy. None is falsy. So: match → True, no match → False.

Notice .strip() is called again here even though the caller already stripped the line. That is defensive programming — the function does not trust that its input is already clean. Harmless redundancy for safety.

🐥
Ducky

Why does this function exist at all? Why not just call HEADER_RE.match() directly in the if-statement?

👩‍💻
Lead

Readability. if is_section_header(stripped) and buffer: reads like English. if bool(HEADER_RE.match(stripped.strip())) and buffer: makes you stop and decode it. Functions with intention-revealing names are one of the highest-value habits you can build as an engineer. The code tells you what it is doing, not how.

Step 10 — extract_tables_as_chunks()

def extract_tables_as_chunks(page, page_num: int, current_section: str) -> list[dict]:
    table_chunks = []
    for table in page.extract_tables() or []:
👩‍💻
Lead

page.extract_tables() detects and returns all tables on the page. Each table is a list of rows. Each row is a list of cell values. Returns None if there are no tables on the page. or [] converts None to an empty list so the loop has nothing to iterate over and does not crash.

        rows = []
        for row in table:
            row_text = " | ".join(str(cell or "").strip() for cell in row)
👩‍💻
Lead

For each row, clean every cell and join them with a pipe separator. Three things on one line:

cell or "" — if a cell is None (an empty table cell), replace it with an empty string. None or "" evaluates to "".

str(...).strip() — convert to string and remove whitespace.

" | ".join(...) — join the cleaned cell values with | between them. A row like ["Symbol", "Min", "Max"] becomes "Symbol | Min | Max".

The for cell in row inside the join() is a generator expression — a compact loop that produces values on the fly without building an intermediate list.

🐥
Ducky

What is the difference between a generator expression and a list comprehension?

👩‍💻
Lead

List comprehension: [str(cell or "").strip() for cell in row] — builds the entire list in memory first, then passes it to join().

Generator expression: str(cell or "").strip() for cell in row (no square brackets) — produces one value at a time as join() requests them. No intermediate list is created.

For join(), the generator is preferred because join() only needs to iterate once — no need to store the whole list. Memory-efficient. For a small table row it makes no practical difference, but it is the idiomatic Python choice.

            if row_text.replace("|", "").strip():
                rows.append(row_text)
👩‍💻
Lead

replace("|", "") removes all pipe characters. .strip() removes whitespace. If the result is a non-empty string, the row had real content. If nothing is left, every cell in the row was empty — skip it. This filters out ghost rows that pdfplumber sometimes detects around borders and formatting artefacts.

        if rows:
            text = "\n".join(rows)
            if len(text) >= MIN_CHUNK_CHARS:
                table_chunks.append({"text": text, "section": current_section, "page": page_num})
    return table_chunks
👩‍💻
Lead

If any rows survived the filter, join them with newlines to form the complete table as a single text block. Apply the 50-char minimum. If it passes, save as a chunk. The entire table is one chunk — not one chunk per row. This is the key design decision: tables must not be split.

Step 11 — tagging and collecting all chunks

            for chunk in text_chunks + table_chunks:
                chunk["chunk_id"] = f"{component}_p{page_num:03d}_c{chunk_index:03d}"
                chunk["component"] = component
                chunk["source_file"] = path.name
                chunk_index += 1
                all_chunks.append(chunk)
👩‍💻
Lead

text_chunks + table_chunks concatenates two lists into one. Both are just Python lists — + joins them.

chunk["chunk_id"] = f"..." — adds a new key to the dict. The chunk was created inside the sub-functions with only text, section, and page. Here we bolt on three more fields.

f"{component}_p{page_num:03d}_c{chunk_index:03d}" — the :03d format spec means: integer, minimum 3 digits, zero-padded. Page 3 → 003. This ensures IDs sort correctly as strings — _p003_ comes before _p010_ alphabetically. Without it, "_p3_" would sort after "_p10_" because string sorting is character-by-character.

chunk_index += 1 is shorthand for chunk_index = chunk_index + 1. Increments the counter so every chunk gets a unique number.

Step 12 — ingest_pdf() returns

    return all_chunks
👩‍💻
Lead

The page loop is done. all_chunks contains every chunk from every page. Execution returns to the line in __main__ that called this function: chunks = ingest_pdf(args.input). The variable chunks now holds the full list.

Step 13 — write JSON to disk

    component = Path(args.input).stem.upper()
    out_path = Path(args.output) / f"{component}.json"
    with open(out_path, "w") as f:
        json.dump(chunks, f, indent=2)
👩‍💻
Lead

Path(args.output) / f"{component}.json" — the / operator on Path objects joins a directory and a filename. Path("data/chunks") / "TPS62902.json" → Path("data/chunks/TPS62902.json"). Safer than string concatenation because it handles OS path separators.

open(out_path, "w") — opens the file for writing. "w" means write mode: creates the file if it does not exist, overwrites it if it does.

json.dump(chunks, f, indent=2) — serialises the Python list of dicts into JSON text and writes it directly to the file object f. indent=2 produces human-readable output with 2-space indentation. Without it, the entire JSON would be one compressed line impossible to read.

Step 14 — print summary

    print(f"Wrote {len(chunks)} chunks -> {out_path}")
    print("Sample chunks:")
    for c in chunks[:3]:
        print(f"  {c['chunk_id']}  section={c['section']!r}  page={c['page']}  len={len(c['text'])}")
👩‍💻
Lead

chunks[:3] — slice notation. Takes elements at index 0, 1, 2. If fewer than 3 chunks exist, returns however many there are without an error.

{c['section']!r} — the !r conversion flag calls repr() on the value before inserting it. For a string, repr() wraps it in quotes: GENERAL prints as 'GENERAL'. This makes it visually obvious you are printing a string, not a number or a boolean.

len(c['text']) — number of characters in the chunk text. Lets you quickly verify that chunks are a reasonable size and not suspiciously short.

🐥
Ducky

I think I understand the whole thing now. But why did we bother separating text chunks and table chunks into two functions? Could we have done it in one?

👩‍💻
Lead

Yes, technically we could have merged them. But they are doing fundamentally different things. Text chunking is about splitting a linear stream of lines by section headers. Table chunking is about taking a 2D structure (rows × cells) and flattening it into one text block. Merging them into one function would have made it harder to understand, test, and change each independently.

The rule: a function should do one thing. When you find yourself writing two distinct algorithms in one function, that is usually a signal to split. Here the split is justified — they work on different data structures (string vs. table object) and have different logic. You can test them in isolation. You can swap one without touching the other.

That is one of the things that separates senior from junior: junior asks "does this work?" Senior asks "can I understand, test, and change each part without touching the rest?"

The Whole Picture

One paragraph: You run the command, argparse reads your flags, the output directory is created, ingest_pdf() opens the PDF and loops over every page — for each page it calls chunk_text_by_section() which scans lines one by one and flushes section-bounded text into chunk dicts when a new header is found, and calls extract_tables_as_chunks() which converts every table into a single pipe-separated text block, then every chunk from both functions gets a unique ID and three metadata fields bolted on and is added to the master list — when all pages are done the master list is serialised to JSON and written to disk.
