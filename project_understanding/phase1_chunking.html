Phase 1 — Structure-Aware PDF Chunking

Why Chunking Matters

The retrieval quality of a RAG system is bounded by chunking quality. A chunk that splits a table across two pieces means a query for "max voltage" might get row 1 (the header) from one chunk and row 2 (the value) from another — neither chunk is useful alone.

Datasheets have explicit sections: Electrical Characteristics, Pin Description, Absolute Maximum Ratings. Splitting on these headers keeps related data together.

Three Approaches Compared

ingest.py USED IN PIPELINE

  • Split on all-caps section header lines (regex)
  • Tables extracted as single chunks via pdfplumber
  • Every chunk tagged: component, section, page
  • Best for: structured technical documents

ingest_alternative1.py

  • Fixed token windows (default 300 tokens)
  • N-token overlap between adjacent chunks
  • No section awareness, page info lost
  • Best for: unstructured prose documents

ingest_alternative2.py

  • NLTK sentence tokenizer groups N sentences
  • Preserves page number of first sentence
  • Misfires on unit abbreviations (3.3V., 2A.)
  • Best for: research papers, narrative text

How ingest.py Works (Key Code)

HEADER_RE = re.compile(r'^[A-Z][A-Z0-9\s\-/]{3,}$')

def is_section_header(line: str) -> bool:
    return bool(HEADER_RE.match(line.strip()))

# When we hit a header line AND there's a buffer, flush the buffer as a chunk
if is_section_header(stripped) and buffer:
    text = " ".join(buffer).strip()
    if len(text) >= MIN_CHUNK_CHARS:
        chunks.append({"text": text, "section": current_section, "page": page_num})
    current_section = stripped
    buffer = []

Interview talking point: "I implemented structure-aware chunking. I split on section headers detected by a regex on all-caps lines, and I extracted tables as single chunks using pdfplumber's extract_tables() so table rows don't split across chunk boundaries. Every chunk is tagged with component name, section name, and page number."
